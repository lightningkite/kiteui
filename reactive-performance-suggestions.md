## 2.1 `invokeAllListeners()` — eliminate defensive `toList()` copy

**File:** `src/commonMain/kotlin/com/lightningkite/reactive/core/abstracts.kt:49-58`

```kotlin
// Current: copies entire listener list on every notification
protected fun invokeAllListeners() {
    listeners.toList().forEach { ... }
}
```

**Problem:** `toList()` allocates a new list on every notification. For frequently-changing reactive
values (e.g., scroll position, animation frames), this creates significant GC pressure.

**Suggested fix:** Iterate the original list with an index-based loop and handle concurrent
modification explicitly. A common pattern is to snapshot only when modification is detected during
iteration (e.g., use a `version` counter that increments on add/remove, and only re-snapshot if
version changed mid-iteration).

```kotlin
// Suggestion: iterate with index, no copy needed in the common (no-modification) case
protected fun invokeAllListeners() {
    var i = 0
    while (i < listeners.size) {
        try {
            listeners[i]()
        } catch (e: Exception) {
            if (e !is CancellationException) Reactive.reportException(e)
        }
        i++
    }
}
```

**Risk:** Low if listeners don't remove themselves during invocation. If they do, the removal
lambda (see 2.2) replaces the slot with a no-op or uses swap-remove, making index-based iteration
safe.

## 2.2 Listener removal — swap-remove instead of `indexOfFirst` + `removeAt`

**File:** `src/commonMain/kotlin/com/lightningkite/reactive/core/abstracts.kt:37-47`

```kotlin
// Current: O(n) scan + O(n) shift
val pos = listeners.indexOfFirst { it === listener }
if (pos != -1) {
    listeners.removeAt(pos)
    ...
}
```

**Problem:** `indexOfFirst` scans the list (O(n)), then `removeAt` shifts all subsequent elements
(O(n)). For reactive values with many listeners, this is O(n) on every unsubscribe.

**Suggested fix:** Use swap-remove (swap the found element with the last element, then removeLast):

```kotlin
return {
    val pos = listeners.indexOfFirst { it === listener }
    if (pos != -1) {
        val last = listeners.lastIndex
        if (pos != last) listeners[pos] = listeners[last]
        listeners.removeAt(last)  // O(1) — removing from end
        if (listeners.isEmpty()) deactivate()
    }
}
```

**Note:** Listener invocation order becomes non-deterministic, which should be fine since listeners
should not depend on invocation order.

## 2.3 Dependency cleanup — use `HashSet` instead of `ArrayList.contains()`

**File:** `src/commonMain/kotlin/com/lightningkite/reactive/context/DependencyTracker.kt`

```kotlin
// Current: ArrayList with O(n) `in` check
protected val usedDependencies = ArrayList<Any?>()
// ...
if (entry.first !in usedDependencies) {  // O(n) per dependency
```

**Problem:** `dependencyBlockEnd()` checks `entry.first !in usedDependencies` for each dependency.
With `ArrayList`, this is O(n) per check, making the whole cleanup O(n^2) in the number of
dependencies.

**Suggested fix:** Change to `HashSet`:

```kotlin
protected val usedDependencies = HashSet<Any?>()
```

The `add()` and `contains()` operations become O(1) average, making cleanup O(n).

**Risk:** Very low. The only operations used are `add()`, `clear()`, and `in` (contains).
`HashSet` supports all of these. The objects stored are `Reactive` instances which use identity
hash by default, which is exactly what's needed.
