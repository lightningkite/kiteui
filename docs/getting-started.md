# Getting started

A KiteUI app is a Kotlin Multiplatform module whose `commonMain` holds the UI: an `app` function that sets up the shell, and pages annotated with `@Routable`.  Each platform has a few lines of entry-point code that hand the app a root view and a theme.  The [example app](../example-app/) is a complete, working setup for web, Android, iOS and desktop.

## Minimal example

```kotlin
// commonMain
val appTheme = Theme.flat2("app", hue = 0.6.turns)

fun ViewWriter.app(navigator: PageNavigator) {
    appBase(navigator) {
        navigatorView(navigator)
    }
}

@Routable("/")
object CounterPage : Page {
    override fun ElementWriter.CanAddTheme.render() {
        val count = Signal(0)
        col {
            h1("Counter")
            text { ::content { "Clicked ${count()} times" } }
            important.button {
                text("Click me")
                onClick { count.value++ }
            }
        }
    }
}
```

```kotlin
// jsMain
fun main() {
    smartRoot(appTheme) { app(PageNavigator { AutoRoutes }) }
}
```

`render()` runs once.  Only the `::content { }` binding reruns when `count` changes.  `AutoRoutes` is generated by the Gradle plugin from every `@Routable` page in `commonMain`.

## Common tasks

### Add the dependencies

```kotlin
// settings.gradle.kts
pluginManagement {
    repositories {
        maven("https://lightningkite-maven.s3.us-west-2.amazonaws.com")
        gradlePluginPortal()
        mavenCentral()
    }
}
dependencyResolutionManagement {
    repositories {
        maven("https://lightningkite-maven.s3.us-west-2.amazonaws.com")
        google()
        mavenCentral()
    }
}
```

```kotlin
// build.gradle.kts of the app module
plugins {
    kotlin("multiplatform")
    kotlin("plugin.serialization")
    id("com.lightningkite.kiteui") version "<version>"
}

kiteui {
    packageName = "com.example.myapp"                        // package of the generated AutoRoutes and Resources
    iosProjectRoot = project.file("../ios/MyApp")            // required only if the module has iOS targets
}

kotlin {
    js { browser(); binaries.executable() }
    // plus android { }, iosArm64(), iosSimulatorArm64(), jvm() as needed
    sourceSets {
        commonMain.dependencies {
            api("com.lightningkite.kiteui:library:<version>")
        }
    }
}
```

The plugin generates `AutoRoutes` (from `@Routable`) and `Resources` (from `src/commonMain/resources/`) into `build/generated/kiteui-*`.  Optional modules: `library-map`, `library-lottie`, `library-camera`.  The desktop target uses `library-compose` (and the `-compose` variants of the optional modules) instead of `library`.

### Write a page with parameters

```kotlin
@Routable("users/{userId}")
class UserPage(val userId: String) : Page {
    override fun ElementWriter.CanAddTheme.render() {
        h1("User $userId")
    }
}
```

Path segments in braces become constructor parameters.  Navigate with `pageNavigator.navigate(UserPage("42"))`.  See [Navigation](navigation.md) for query parameters, back, and app shells with tabs or a sidebar.

### Start the app on each platform

Web (`jsMain`).  `smartRoot` hydrates server-rendered HTML if present and otherwise renders from scratch; `root(theme) { }` always renders from scratch.

```kotlin
fun main() {
    smartRoot(appTheme) { app(PageNavigator { AutoRoutes }) }
}
```

Put an `index.html` in `src/jsMain/resources/` that loads your bundle as a module and sets `<base href="/">` so deep links resolve.  See [`example-app/src/jsMain/resources/index.html`](../example-app/src/jsMain/resources/index.html).

Android (`androidMain`).  With AGP 9 the installable app is a separate `com.android.application` module that depends on the KMP module (see [`example-app-android`](../example-app-android/)).

```kotlin
class MainActivity : KiteUiActivity() {
    override val mainNavigator = PageNavigator { AutoRoutes }
    override val theme: ReactiveContext.() -> Theme get() = { appTheme }

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        with(viewWriter) { app(mainNavigator) }
    }
}
```

iOS (`iosMain`).  Export `library` from the framework (`binaries.framework { export(project(":library")) }` or the published artifact), then call this from your `UIViewController`.

```kotlin
fun root(viewController: UIViewController) {
    viewController.setup(appTheme) { app(PageNavigator { AutoRoutes }) }
}
```

```swift
class ViewController: UIViewController {
    override func viewDidLoad() {
        super.viewDidLoad()
        App_iosKt.root(viewController: self)
    }
}
```

Desktop (`jvmMain`, with `library-compose` and `compose.desktop.currentOs`).

```kotlin
fun main() {
    val navigator = PageNavigator { AutoRoutes }
    kiteUiWindow("com.example.myapp", title = "My App", theme = { appTheme }) { app(navigator) }
}
```

### Use resources

Files under `src/commonMain/resources/` become typed properties named after their path: `images/snowyBackground.jpg` is `Resources.imagesSnowyBackground`.  Images (`png`, `jpg`, `webp`), vectors (`svg`), fonts (`ttf`, `otf`), audio (`mp3`, `ogg`, `wav`) and video (`mp4`) are supported.

```kotlin
image { source = Resources.imagesSnowyBackground; description = "Snowy hills" }
```

### Run the example app

```bash
./gradlew :example-app:jsViteDev                   # web dev server (Vite), handles SPA routing
./gradlew :example-app-android:installDebug         # Android device or emulator
./gradlew :example-app-desktop:run                  # desktop window
./gradlew :example-app:ssrServerRun                 # server-side rendering demo
```

For iOS, open `example-app-ios/` in Xcode.  The example's web build uses Vite through the `io.github.turansky.kfc.application` plugin; serve any KiteUI web build with SPA fallback to `index.html`, or deep links 404.

## Gotchas

- `render()` is not a React render function: it runs once per page instance.  Put changing values in `Signal`s and read them inside bindings (`::content { }`).  See [Reactivity](reactivity.md).
- `packageName` must be set, or the build fails.  A module with iOS targets must also set `iosProjectRoot`, which the plugin uses to copy resources into the Xcode project.
- `appBase` (or `appNav`, or one of the `nav*` shells, which call it) must wrap the app.  It sets up the page navigator and the overlay frame that dialogs and toasts open in; without it, `dialog { }` and `toast(...)` throw.
- `@Routable` pages must live in `commonMain/kotlin` of the module the plugin is applied to; `AutoRoutes` is generated by scanning those sources.
